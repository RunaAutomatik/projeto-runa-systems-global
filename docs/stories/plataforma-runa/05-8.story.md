# Story 05-8 — Auth + onboarding pages UI

## Context

Authentication pages (Clerk sign-in/sign-up) must match the forest theme visually. Post-signup, users are redirected to a welcome/onboarding page. Users without an active subscription need a dedicated "access denied" page with a clear CTA to purchase RUNA.

## Acceptance Criteria

- [x] AC1: Clerk sign-in and sign-up components have `appearance` prop matching forest theme — `colorBackground: '#080C09'`, `colorPrimary: '#3D4842'`, card background `#111712`
- [x] AC2: Welcome/onboarding page exists for post-signup redirect — clear first-step instructions for new mentees
- [x] AC3: Access denied page (`/sem-acesso` or equivalent) exists for users without active subscription — includes CTA pointing to RUNA checkout (R$ 7.000) or WhatsApp
- [x] AC4: `npm run build` passes without type errors

## File List

- `apps/plataforma-runa/app/(public)/entrar/[[...sign-in]]/page.tsx` — Clerk sign-in with forest appearance
- `apps/plataforma-runa/app/(public)/cadastrar/[[...sign-up]]/page.tsx` — Clerk sign-up with forest appearance
- `apps/plataforma-runa/app/(protected)/bem-vindo/page.tsx` — welcome/onboarding page (3 first steps)
- `apps/plataforma-runa/app/(public)/sem-acesso/page.tsx` — access denied page with R$ 7.000 CTA

## Dev Notes

- Clerk `appearance.variables` full set: `colorBackground`, `colorPrimary`, `colorText`, `colorTextSecondary`, `colorInputBackground`, `colorInputText`
- Clerk `appearance.elements` can target specific UI parts: `card`, `headerTitle`, `formButtonPrimary`
- Access denied page: NO lorem ipsum, NO generic text — specific messaging about RUNA program
- Welcome page: outline the 3 first steps (check calendar for first session, download prerequisite, join WhatsApp group)

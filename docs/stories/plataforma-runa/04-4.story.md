# Story 04-4 — Admin — Bunny.net video upload via TUS

## Context

Arthur needs to upload session recordings to Bunny.net directly from the admin panel and associate the resulting `bunny_video_id` with a session record.

Large video files (90-min recordings can be 2–5 GB) must NOT be proxied through the Next.js server. The TUS protocol enables resumable direct browser→Bunny uploads. The server only creates the Bunny video entry and returns the TUS upload URL; the client streams bytes directly to Bunny.

## Bunny API Flow

```typescript
// POST /api/admin/upload-video
// 1. Create video object in Bunny
const res = await fetch(
  `https://video.bunnycdn.com/library/${BUNNY_LIBRARY_ID}/videos`,
  {
    method: 'POST',
    headers: { AccessKey: BUNNY_API_KEY, 'Content-Type': 'application/json' },
    body: JSON.stringify({ title: sessionTitle }),
  }
)
const { guid } = await res.json()  // guid = bunny_video_id

// 2. Return TUS upload URL to client
return NextResponse.json({
  bunny_video_id: guid,
  tus_upload_url: `https://video.bunnycdn.com/tusupload`,
})

// Client: use tus-js-client with headers:
// AuthorizationSignature (HMAC-SHA256), AuthorizationExpire, VideoId, LibraryId
```

## Dev Notes

- Install: `npm install tus-js-client` (preferred — lighter than full Uppy)
- Bunny TUS endpoint requires 4 headers: `AuthorizationSignature`, `AuthorizationExpire`, `VideoId`, `LibraryId`
- `AuthorizationSignature` = SHA256(HMAC(BUNNY_API_KEY, BUNNY_LIBRARY_ID + bunny_video_id + expire))
- The HMAC computation must be done server-side — never send `BUNNY_API_KEY` to the client
- The API route generates the HMAC and returns it alongside the TUS URL
- Refer to Bunny.net TUS upload docs: https://docs.bunny.net/reference/tus-resumable-upload

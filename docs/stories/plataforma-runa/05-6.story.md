# Story 05-6 — Admin panel UI pass — tema forest

## Context

The admin panel (`app/admin/`) uses the forest theme but must have a visually distinct identity from the mentee dashboard — higher density, data-first, table-centric. The admin UI was functionally implemented in Epic 04; this story applies the design pass: consistent tokens, loading/empty/error states, form styling, and sidebar navigation polish.

## Acceptance Criteria

- [x] AC1: `app/admin/` routes use `tema forest` with visually distinct density and layout from the mentee dashboard — admin feels data-dense, mentee feels spacious
- [x] AC2: All tables have three states: loading (skeleton rows), empty (composed empty state), error (inline error with retry action)
- [x] AC3: All forms use label-above-input pattern, helper text optional, error text inline below the field — no floating labels
- [x] AC4: Admin sidebar navigation is clearly organized with sections: Dashboard, Mentorados, Conteúdo — active state and hover state both implemented
- [x] AC5: `npm run build` passes without type errors

## Dev Notes

- Admin accent should be slightly more visible than mentee — use `#4A5C4E` (slightly lighter sage) or increase border contrast
- Table rows: `hover:bg-surface-2` transition — no neon hover effects
- Skeleton row height must match real row height exactly — measure real row first
- Error states: red-tinted text (`#C95454` or similar), not pure red — muted to match forest palette
- Sidebar: `border-r border-border` separator — no drop shadow

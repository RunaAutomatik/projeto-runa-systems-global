# Story 04-9 — Resend — onboarding email pós-pagamento

## Context

After the Stripe webhook fires and the 3-way sync completes (Story 04-8), the new mentee receives a transactional welcome email via Resend. The email is triggered by the webhook handler calling `triggerOnboardingEmail({ userId, menteeSlug, email })` — already referenced in Story 04-8's acceptance criteria.

The email is built with React Email so it renders consistently across clients. It delivers the platform link, next steps, and Arthur's contact.

## Acceptance Criteria

- [x] `npm install resend @react-email/components` applied
- [x] `emails/OnboardingEmail.tsx` React Email component created
- [x] OnboardingEmail renders:
  - Greeting: "Bem-vindo ao RUNA OS, [firstName]!"
  - Body: brief description of what happens next (sessões começam na semana X, plataforma disponível agora)
  - CTA button: "Acessar plataforma →" linking to `${NEXT_PUBLIC_APP_URL}/mentorados/[menteeSlug]`
  - Próximos passos (3 bullet points): (1) acesse a plataforma, (2) aguarde Arthur marcar a Sessão 01, (3) qualquer dúvida responda este email
  - Footer: nome Arthur Runa + contato
- [x] `lib/emails.ts` exports `triggerOnboardingEmail({ userId, menteeSlug, email })` async function (file was `emails.ts` per Story 04-8 import)
- [x] `triggerOnboardingEmail` calls `resend.emails.send({ from: 'arthur@runa.ai', to: email, subject: 'Bem-vindo ao RUNA OS', react: OnboardingEmail({ menteeSlug, firstName }) })`
- [x] `firstName` derived from `email.split('@')[0]` (same slug logic — simple heuristic, no Clerk fetch needed)
- [x] `RESEND_API_KEY` env var used — never exposed client-side
- [x] If Resend call fails, error is logged but webhook still returns 200 (non-blocking)
- [x] `npm run build` passes with no TypeScript errors
- [x] `npm run lint` passes

## Dev Notes

- Resend client init: `new Resend(process.env.RESEND_API_KEY!)`
- `from` domain must be verified in Resend dashboard — use `arthur@runa.ai` (or `noreply@runa.ai` if subdomain configured)
- React Email components: `@react-email/components` provides `Html`, `Head`, `Body`, `Container`, `Button`, `Text`, `Section`, `Hr`
- The `triggerOnboardingEmail` function is called from `app/api/webhooks/stripe/route.ts` (Story 04-8) — it already has `import { triggerOnboardingEmail } from '@/lib/email'` in Story 04-8's AC
- Email failure must NOT cause webhook to return non-200 — Stripe would retry the entire webhook causing duplicate tier upgrades
- `firstName` is cosmetic only — no need for precise extraction beyond the `@` split

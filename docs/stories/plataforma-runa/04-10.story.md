# Story 04-10 — Lucas Pesto — seed histórico completo (supersede 03-8)

## Context

Lucas Pesto is the first RUNA mentee. His session history (S01–S09+), deliverables, and profile data exist in `SÍRIOS/MENTORADOS/Lucas Pesto/` but not yet in Supabase. Story 03-8 was created for this migration but blocked pending Epic 04 admin infrastructure. This story supersedes 03-8 entirely.

The seed script runs once via `npx ts-node` or `tsx` and uses the Supabase service role key to bypass RLS. It is idempotent — running it twice produces no duplicates. After this story is Done, Story 03-8 status is updated to Deprecated.

## Acceptance Criteria

- [x] `seeds/seed-lucas-pesto.ts` script created at monorepo root (not inside `apps/`)
- [x] Script reads Lucas Pesto's data from `SÍRIOS/MENTORADOS/Lucas Pesto/` — sessions and deliverables hardcoded in the script (no runtime filesystem read)
- [x] Profile upsert: ensures `profiles` row exists for Lucas with `tier = 'mentee'`, `mentee_slug = 'lucas-pesto'`
- [x] Sessions upsert: 9 sessions (S01–S09) with fields: `mentee_id`, `session_number`, `title`, `status` (completed/scheduled), `session_date`, `bunny_video_id` (if recording available, else null), `notes`
- [x] Deliverables upsert: all known deliverables linked to correct session_number
- [x] Upsert uses `{ onConflict: 'mentee_id,session_number' }` for sessions — idempotent
- [x] Upsert uses `{ onConflict: 'id' }` for deliverables — idempotent
- [x] Script uses `SUPABASE_SERVICE_ROLE_KEY` env var (bypasses RLS) — reads from `apps/plataforma-runa/.env.local`
- [x] Script logs each upserted record and final summary: `X sessions upserted, Y deliverables upserted`
- [x] Execution: `npx tsx seeds/seed-lucas-pesto.ts` completes without errors
- [x] After seed: Lucas's data visible in `/admin/mentorados/[id]` admin view (Story 04-3 UI)
- [x] After seed: Story 03-8 status updated to `Deprecated` in its frontmatter
- [x] `npm run build` passes (seed script does not affect build — it is not imported by the app)

# Story 05-10 — Responsive + mobile pass

## Context

All layouts implemented in 05-4 through 05-8 must work on a 390px viewport (iPhone 15 baseline) without horizontal overflow. Touch targets must meet the 44px minimum. Typography must scale responsively via `clamp()`. This is the final pass before the impeccable audit (05-9) confirms quality.

## Acceptance Criteria

- [ ] AC1: All layouts function at 390px viewport width with no horizontal overflow — test all routes: landing page, dashboard, admin, biblioteca, auth pages
- [ ] AC2: All interactive elements (buttons, nav items, cards, form inputs) have a minimum 44px touch target size — use `min-h-[44px] min-w-[44px]` or padding to reach target
- [ ] AC3: Display/headline typography uses `clamp()` for responsive scaling — e.g., `clamp(1.75rem, 5vw, 3.5rem)` — no fixed large rem values that overflow on mobile
- [ ] AC4: Inline images (if any in landing page hero) stack below headline text on viewports below 768px
- [ ] AC5: Navigation collapses to mobile menu (hamburger or bottom navigation bar) on viewports below 768px
- [ ] AC6: `npm run build` passes without type errors

## File List

- All files modified in 05-4 through 05-8 may receive responsive fixes
- `apps/plataforma-runa/components/navigation/mobile-nav.tsx` — mobile navigation (create if needed)

## Dev Notes

- Use `overflow-x: hidden` on `<body>` as a safety net — but fix the root cause, not just the symptom
- Tailwind responsive prefix order: mobile-first (`text-2xl md:text-4xl`)
- `clamp()` formula: `clamp(min, preferred, max)` — preferred is usually a vw-based value
- Bottom navigation pattern for mobile dashboard: 3-4 icons, `fixed bottom-0 w-full bg-surface-1 border-t border-border`
- Hamburger for landing page: simpler, clean slide-in menu matching papel theme
- Test with browser DevTools device emulation at 390×844 (iPhone 15)

# Impeccable — Design Quality Usage Rules

## What it is

Design quality skill for AI coding agents (Claude Code, Cursor, Gemini CLI, Codex).
Solves the critical problem of AI-generated UI looking generic — injects design vocabulary,
detects 27 deterministic anti-patterns, and provides 23 refinement commands.

Repo: https://github.com/pbakaus/impeccable | License: Apache 2.0

## Pipeline Position

```
taste-design (DESIGN.md)
  → stitch-design (generate screen)
  → impeccable audit (detect anti-patterns)           ← THIS TOOL
  → [ISSUES] → polish / typeset / colorize / layout   ← REFINEMENT
  → [CLEAN]  → @dev integrates HTML/CSS into codebase
```

**Relationship to `ui-ux-pro-max`:**
- `ui-ux-pro-max` = *creator* — generates wireframes, components, design systems
- `impeccable`    = *auditor/refiner* — detects anti-patterns in already-generated UI
- These are complementary, never conflicting. `ui-ux-pro-max` generates → `impeccable` quality-gates.

## Commands Quick Reference

| Command | When to Use |
|---------|-------------|
| `/impeccable audit` | First pass — detect all 27 anti-pattern categories |
| `/impeccable polish` | Full surface refinement (radius, shadows, spacing) |
| `/impeccable typeset` | Typography hierarchy fix |
| `/impeccable colorize` | Color system refinement |
| `/impeccable animate` | Motion + micro-interactions |
| `/impeccable layout` | Grid, spacing, visual hierarchy |
| `/impeccable critique` | Narrative critique (WHY it feels wrong) |
| `/impeccable teach` | Explain design concepts interactively |
| `/impeccable live` | Browser HMR iteration — 3 variants per element (alpha) |
| `/impeccable pin` | Pin decision to DESIGN.md |

Additional commands: `clarify`, `distill`, `harden`, `optimize`, `adapt`, `extract` — see skill SKILL.md for full list.

## CLI — Pre-commit / CI

```bash
# Directory scan (JSX/TSX/HTML/CSS)
npx impeccable detect src/ --json

# URL scan (staging)
npx impeccable detect https://staging.example.com --json

# Output format:
# {"antiPatterns": [{"rule": "generic-gradient", "location": "src/Hero.tsx:42", "severity": "high"}]}
```

Severity levels: `high` / `medium` / `low`. Use `--json` for deterministic CI output.
**Owner:** `@devops` for pre-commit hook configuration.

## 27 Anti-Pattern Categories

| Category | Examples |
|----------|---------|
| **AI Aesthetic** | Generic gradients, glassmorphism overuse, purple glow shadows |
| **Typography** | Inter in premium contexts, wrong hierarchy, line-height issues |
| **Color** | Neon accents, no clear primary, saturation > 80% |
| **Layout** | 3-equal-cards, centered hero on complex pages, no spatial zones |
| **Animation** | Bounce keyframes, excessive transitions, no motion purpose |
| **Quality** | Missing hover states, no empty states, no loading states |

## When to Use

**USE impeccable when:**
- Any screen generated by stitch-design exits before delivery to @dev
- Running QA on frontend code before PR
- Client-facing RUNA SYSTEMS teaching content needs design quality gate
- Running `/impeccable live` for browser-based iteration on a specific element

**Do NOT use impeccable when:**
- Backend-only code — CLI only processes JSX/TSX/HTML/CSS
- Text/copy generation — design-only tool, no copywriting capability
- First-time project setup — run `taste-design` first to create `DESIGN.md`
- MCP or database operations — wrong tool entirely

---

## Anti-Patterns

❌ **Running audit without DESIGN.md** — output is generic, not brand-aware. Run `taste-design` first.

❌ **Using `/impeccable live` in CI** — interactive browser mode, breaks non-interactive pipelines. Use `npx impeccable detect --json` for CI.

❌ **Running on backend-only code** — only processes JSX/TSX/HTML/CSS. Will produce no results on Python/Go/SQL.

❌ **Skipping `taste-design` before `/impeccable pin`** — `DESIGN.md` must exist before pinning decisions.

❌ **Using impeccable for copy generation** — design vocabulary + anti-pattern detection only.

❌ **@devops configuring pre-commit hook before `@ux-design-expert` runs first audit** — first audit must pass manually; then automate.

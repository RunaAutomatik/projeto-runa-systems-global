# Google Stitch — Usage Rules

## What is Stitch

Google Stitch is an AI design tool from Google Labs that generates high-fidelity UI screens
(HTML/CSS) from natural language prompts. It maintains design system consistency across an
entire project via a `DESIGN.md` source of truth.

Access: https://labs.google.com/stitch
MCP identifier: `StitchMCP`

## Installed Skills (global)

| Skill | Path | Purpose |
|-------|------|---------|
| `stitch-design` | `~/.agents/skills/stitch-design` | Unified entry: generate screens, edit screens, create DESIGN.md |
| `stitch-loop` | `~/.agents/skills/stitch-loop` | Autonomous iterative site builder via baton system |
| `taste-design` | `~/.agents/skills/taste-design` | Generate opinionated anti-generic DESIGN.md files |

## MCP Status — REQUIRED BEFORE USE

> ⚠️ **StitchMCP is NOT configured.** All three skills require the Stitch MCP server.
> Without it, any `stitch-design`, `stitch-loop`, or `taste-design` invocation will fail
> when calling tools like `generate_screen_from_text`, `edit_screens`, `list_projects`.

**Setup required (one time):**
1. Go to https://labs.google.com/stitch and create or access a project
2. Follow the MCP setup instructions at the Stitch site to get the MCP server config
3. Add to `~/.claude.json` under `mcpServers`:
   ```json
   "StitchMCP": {
     "command": "...",
     "args": [...]
   }
   ```
4. Restart Claude Code

Until MCP is configured, only use `taste-design` for generating DESIGN.md files
(it can produce design system documents without MCP when used as a reference writer).

## When to Use Stitch

### USE Stitch when:
- Building a new page/screen and visual fidelity matters before coding
- Client needs to approve a design before implementation
- Creating a SITE$ product deliverable (UI mockup → code)
- Iterating on multiple pages of a site autonomously (stitch-loop)
- User asks for "design" a screen (not "code" it)

### Do NOT use Stitch when:
- Task is "implement" or "code" → use `ui-ux-pro-max` + React/Tailwind directly
- Project already has an existing component library → build with existing components
- Quick one-off component → code directly, no mockup step needed
- User asks for code, not design

### Decision tree:
```
User asks for UI work
  ├── "Design / mockup / show me" → Stitch (Uma)
  │     ├── First time on project → taste-design → stitch-design
  │     └── Multi-page site → stitch-loop
  └── "Code / implement / build" → ui-ux-pro-max + @dev
```

## Workflow — First Time on a Project

```
1. Uma runs /taste-design → creates .stitch/DESIGN.md
2. Uma runs /stitch-design → generates screens with StitchMCP
3. Output: .stitch/designs/{page}.html + screenshot
4. @dev integrates HTML/CSS into React/Tailwind components
```

## Workflow — Autonomous Multi-Page Build (stitch-loop)

```
1. Uma creates .stitch/SITE.md (site vision + roadmap)
2. Uma runs /taste-design → .stitch/DESIGN.md
3. Uma creates .stitch/next-prompt.md (first page task)
4. @dev runs /stitch-loop → generates page, passes baton
5. Next iteration reads .stitch/next-prompt.md → repeat
```

## File Structure Created by Stitch Skills

```
.stitch/
├── DESIGN.md        ← Source of truth (generated by taste-design)
├── SITE.md          ← Site vision and roadmap (for stitch-loop)
├── next-prompt.md   ← Baton file (stitch-loop iteration tasks)
└── designs/
    ├── home.html    ← Generated screens
    ├── home.png     ← Screenshots
    └── ...
```

## Prompt Engineering Rules for Stitch

The `stitch-design` skill enhances prompts automatically, but key principles:

1. **Always include DESIGN SYSTEM block** copied from `.stitch/DESIGN.md`
2. **Name each section** (Header, Hero, Features, Footer)
3. **Specify device type** (DESKTOP / MOBILE / TABLET)
4. **Avoid vague terms** — "nice header" → "sticky nav with glassmorphism and centered logo"

### Banned patterns (taste-design enforces):
- Inter font in premium/creative contexts → use Geist, Outfit, Cabinet Grotesk, Satoshi
- Purple/neon glows → use single accent with saturation < 80%
- Centered hero when variance > 4 → force split screen or asymmetric layout
- Generic 3-equal-cards row → use 2-column zig-zag or asymmetric grid
- Overlapping elements → every element in its own spatial zone

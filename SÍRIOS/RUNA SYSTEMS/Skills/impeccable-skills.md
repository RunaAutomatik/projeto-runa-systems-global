## Overview

**Impeccable** (`pbakaus/impeccable`) is a design quality skill for AI coding agents (Claude Code, Cursor, Gemini CLI, Codex). It solves the critical problem of AI-generated UI looking generic by injecting design vocabulary, detecting 27 deterministic anti-patterns, and providing 23 refinement commands.

**Problem it solves:** `@ux-design-expert` (Uma) and `@dev` (Dex) had no systematic visual quality audit layer. UI could pass tests but fail aesthetically. Impeccable closes that gap with a deterministic CLI + refinement commands.

**License:** Apache 2.0 — bundleable for RUNA SYSTEMS client delivery.
**Repo:** https://github.com/pbakaus/impeccable

## Skills / Commands

### Audit
| Command | Purpose |
|---------|---------|
| `/impeccable audit` | Full first-pass — detect all 27 anti-pattern categories |
| `/impeccable critique` | Narrative critique (explains WHY something feels wrong) |
| `/impeccable teach` | Explain design concepts interactively |

### Refinement
| Command | Purpose |
|---------|---------|
| `/impeccable polish` | Full surface refinement — radius, shadows, spacing |
| `/impeccable typeset` | Typography hierarchy fix |
| `/impeccable colorize` | Color system refinement |
| `/impeccable animate` | Motion + micro-interactions |
| `/impeccable layout` | Grid, spacing, visual hierarchy |
| `/impeccable clarify` | Improve visual clarity and legibility |
| `/impeccable distill` | Reduce visual noise, increase focus |
| `/impeccable harden` | Strengthen brand consistency |
| `/impeccable optimize` | Performance and rendering quality |
| `/impeccable adapt` | Adapt design to a target context or device |
| `/impeccable extract` | Extract design tokens to DESIGN.md |

### Integration
| Command | Purpose |
|---------|---------|
| `/impeccable live` | Browser HMR iteration — 3 variants per element (alpha, @dev only) |
| `/impeccable pin` | Pin decision to DESIGN.md |

## CLI (Pre-commit / CI)

```bash
# Directory scan (JSX/TSX/HTML/CSS)
npx impeccable detect src/ --json

# URL scan (staging)
npx impeccable detect https://staging.example.com --json

# Output format:
# {"antiPatterns": [{"rule": "generic-gradient", "location": "src/Hero.tsx:42", "severity": "high"}]}
```

**Severity levels:** `high` / `medium` / `low`
**Owner:** `@devops` for pre-commit hook configuration
**Flag `--json`:** Produces deterministic output for CI integration

## 27 Anti-Pattern Categories

| Category | Examples |
|----------|---------|
| **AI Aesthetic** | Generic gradients, glassmorphism overuse, purple glow shadows |
| **Typography** | Inter in premium contexts, wrong hierarchy, line-height issues |
| **Color** | Neon accents, no clear primary, saturation > 80% |
| **Layout** | 3-equal-cards, centered hero on complex pages, no spatial zones |
| **Animation** | Bounce keyframes, excessive transitions, no motion purpose |
| **Quality** | Missing hover states, no empty states, no loading states |

## Pipeline Position

```
taste-design (DESIGN.md)
  → stitch-design (generate screen)
  → impeccable audit (detect anti-patterns)          ← THIS SKILL
  → [ISSUES] → /impeccable polish / typeset / colorize / layout
             → re-audit
  → [CLEAN]  → @dev integrates HTML/CSS into codebase
```

**Relationship to `ui-ux-pro-max`:**
- `ui-ux-pro-max` = *creator* — generates wireframes, components, design systems
- `impeccable` = *auditor/refiner* — detects anti-patterns in already-generated UI
- These are complementary. `ui-ux-pro-max` generates → `impeccable` quality-gates.

## Decision Tree

```
UI was generated (stitch-design or ui-ux-pro-max output)?
  ├── YES → /impeccable audit (Uma)
  │     ├── Anti-patterns found?
  │     │     ├── YES → /impeccable polish / typeset / colorize / layout → re-audit
  │     │     └── NO  → @dev integrates
  │     └── Want to pin a design decision? → /impeccable pin
  └── NO (backend, copy, database work) → impeccable not applicable

CI/pre-commit gate?
  └── @devops configures: npx impeccable detect src/ --json
```

**When NOT to use:**
- Backend-only code — CLI processes JSX/TSX/HTML/CSS only
- Text/copy generation — design-only tool
- First project setup — run `taste-design` first to create `DESIGN.md`

## Anti-Patterns

❌ **Running audit without DESIGN.md** — output is generic, not brand-aware. Run `taste-design` first.

❌ **Using `/impeccable live` in CI** — interactive browser mode, breaks non-interactive pipelines. Use `npx impeccable detect --json` for CI.

❌ **Running on backend-only code** — only processes JSX/TSX/HTML/CSS. No results on Python/Go/SQL.

❌ **Skipping `taste-design` before `/impeccable pin`** — `DESIGN.md` must exist before pinning decisions.

❌ **Using impeccable for copy generation** — design vocabulary + anti-pattern detection only.

❌ **@devops configuring pre-commit hook before first manual audit** — run first audit manually; then automate.

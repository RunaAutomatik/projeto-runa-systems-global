## M1 — Mindset: Como você pensa sobre IA

> *Antes de instalar qualquer ferramenta, você precisa mudar como opera mentalmente. Ferramentas instaladas por mentes não preparadas viram ferramentas paradas.*

---

### Princípio 1.1 — Default Shift

**O que é:** Toda vez que você for fazer algo repetitivo ou que exige processamento de informação, a pergunta padrão passa a ser: *"Como a IA faz isso junto comigo?"* — não *"Eu faço ou a IA faz?"*

**Exercício:**

```
1. _______________________________________________
2. _______________________________________________
3. _______________________________________________
```

Para cada uma, responda: você perguntou *"como a IA faz isso junto comigo?"* antes de começar?

```
1. [ ] Sim  [ ] Não  — Por quê? _________________________
2. [ ] Sim  [ ] Não  — Por quê? _________________________
3. [ ] Sim  [ ] Não  — Por quê? _________________________
```

**Caso Alpha® (CREATOR$):** Lucas precisava criar pautas semanais para 33 clientes. Default antigo: abrir planilha, pensar do zero. Default novo: "Claude, com base nos temas de cada cliente, gera 5 pautas por cliente para a semana de [data] — use o padrão da semana passada como referência." Tempo: 4h → 22min.


### Princípio 1.2 — Function Breakdown

**O que é:** Toda tarefa complexa tem camadas. Antes de delegar para a IA, você precisa saber quais camadas exigem julgamento humano e quais são mecânicas. Você não delega a tarefa — você delega as camadas mecânicas.

**Exercício:**

Escolha uma tarefa complexa do seu negócio (ex: fechar proposta, criar conteúdo, fazer relatório de cliente):

```
Tarefa escolhida: ______________________________________
```

Quebre em camadas. Para cada camada, marque se é Mecânica (M) ou Julgamento (J):

```
Camada 1: ____________________________  [ M ]  [ J ]
Camada 2: ____________________________  [ M ]  [ J ]
Camada 3: ____________________________  [ M ]  [ J ]
Camada 4: ____________________________  [ M ]  [ J ]
Camada 5: ____________________________  [ M ]  [ J ]
```

Quais camadas você pode delegar para a IA agora?

```
Delegar: _______________________________________________
Manter comigo: _________________________________________
```

**Caso Alpha® (CREATOR$):** Criar um post de Instagram tem 6 camadas: (1) definir tema [J], (2) pesquisar referências [M], (3) estruturar o gancho [J], (4) redigir o corpo [M], (5) adaptar para o formato [M], (6) revisar voz [J]. Três camadas mecânicas → delegadas para FREYJA. Três de julgamento → Arthur.

### Princípio 1.3 — Curiosity Rule

**O que é:** Quando um agente de IA entrega algo que não era o esperado, a primeira reação não é frustração — é curiosidade. *"Por que produziu isso? O que no meu input causou esse output?"* Quem itera aprende. Quem desiste fica para trás.

**Exercício:**

Você já tentou usar IA e ficou frustrado com o resultado. Descreva um caso:

```
O que você pediu: _______________________________________
O que recebeu: __________________________________________
O que fez depois: [ ] Tentou de novo  [ ] Desistiu  [ ] Ajustou o pedido
```

Com a Curiosity Rule, o que você faria diferente?

```
Ajuste que eu teria feito no meu pedido: ________________
_________________________________________________________
```

**Regra prática:** Se o output não foi o esperado, a pergunta é sempre *"o que está faltando no meu contexto?"* — não *"a IA não funciona."*

## M2 — Method: Como você opera com IA

> *Mindset sem método é intenção. Método é a sequência que transforma intenção em resultado repetível.*

---

### Princípio 2.1 — EAD: Eliminar → Automatizar → Delegar

**O que é:** Antes de automatizar qualquer processo, pergunte: *esse processo precisa existir?* Automatizar desperdício é desperdício automatizado. A sequência correta é sempre: Eliminar primeiro. Só automatize o que sobreviveu. Só delegue o que não pode ser automatizado.

```
ELIMINAR  →  AUTOMATIZAR  →  DELEGAR
   ↓               ↓              ↓
"Isso precisa   "Isso é       "Isso exige
  existir?"    repetível e    julgamento
               mensurável?"   humano?"
```

**Exercício — Auditoria EAD:**

Liste 5 processos recorrentes do seu negócio (semanal/mensal):

```
Processo 1: _____________________________________________
  [ ] Eliminar  [ ] Automatizar  [ ] Delegar

Processo 2: _____________________________________________
  [ ] Eliminar  [ ] Automatizar  [ ] Delegar

Processo 3: _____________________________________________
  [ ] Eliminar  [ ] Automatizar  [ ] Delegar

Processo 4: _____________________________________________
  [ ] Eliminar  [ ] Automatizar  [ ] Delegar

Processo 5: _____________________________________________
  [ ] Eliminar  [ ] Automatizar  [ ] Delegar
```

**Candidato EAD #1** — o processo com maior potencial de automação agora:

```
Processo: _______________________________________________
Por que automatizar? ____________________________________

Quanto tempo leva por semana: ___________________________
```

**Caso Alpha® (CREATOR$):** Lucas tinha reunião de briefing com cada cliente toda segunda. EAD: (E) eliminar reuniões — substituir por formulário de briefing automatizado. (A) automatizar processamento do formulário → Claude gera pautas. (D) delegar aprovação das pautas → cliente aprova assincronamente. Resultado: 8h/semana → 45min.

### Princípio 2.2 — Mapeamento de Processo

**O que é:** Antes de construir qualquer automação ou agente, você mapeia o processo como ele existe hoje — incluindo os pontos de decisão. Sem mapa, você automatiza o caminho errado.

**Template de mapeamento (preencha para o seu candidato EAD #1):**

```

__________________________________________________________

PASSOS (em ordem):
1. _____________________________________________________
2. _____________________________________________________
3. _____________________________________________________
4. _____________________________________________________
5. _____________________________________________________

PONTOS DE DECISÃO (onde alguém precisa julgar algo?):
1. _____________________________________________________
2. _____________________________________________________

OUTPUT (o que o processo produz?):
__________________________________________________________

FREQUÊNCIA: ____________________________________________
TEMPO ATUAL: ___________________________________________
DONO DO PROCESSO: _______________________________________
```

---

### Princípio 2.3 — Autonomy Spectrum (L0–L4)

**O que é:** Todo agente ou automação começa no nível mais baixo de autonomia que resolve o problema. Você avança o nível quando o nível anterior está funcionando de forma consistente.

```
L0  MANUAL       — Você faz tudo manualmente
L1  ASSISTIDO    — IA sugere, você decide e executa
L2  SUPERVISIONADO — IA executa, você revisa antes de publicar/enviar
L3  MONITORADO   — IA executa, você revisa amostras e relatórios
L4  AUTÔNOMO     — IA executa com Kill Switch disponível
```

**Exercício:**

Para o processo que você mapeou no 2.2, qual nível de autonomia é realista *agora*?

```
Nível atual do processo: L ___
Nível realista em 30 dias: L ___
Critério para avançar de nível: __________________________
__________________________________________________________
```

**Regra de ouro:** O erro mais comum é pular para L4 sem passar por L1–L3. A confiança em um agente é construída em camadas. Sem histórico, não existe confiança.

**Caso Alpha® (CREATOR$):** O agente de pautas de Lucas começou em L1 (Lucas aprovava cada pauta) → passou para L2 após 3 semanas (aprovava por lote na segunda) → hoje está em L3 (revisa relatório semanal, intervém apenas em exceções).

---

### Princípio 2.4 — KPI por Automação

**O que é:** Toda automação ou agente deve ter um número que diz se está funcionando. Sem KPI, você não sabe quando desligar.

**Para o processo que você mapeou:**

```
KPI principal (o que mede sucesso?): ____________________
Valor atual (antes da automação): _______________________
Meta em 30 dias: ________________________________________
Frequência de revisão: __________________________________
Critério para desligar (Kill Switch): ___________________
```

**Exemplos de KPI por tipo de processo:**

| Processo | KPI |
|----------|-----|
| Criação de conteúdo | Posts publicados / hora investida |
| Atendimento | Tempo de resposta + taxa de resolução |
| Onboarding de cliente | Tempo até primeira entrega |
| Relatórios | Horas/semana em geração manual |
| Prospecção | Leads qualificados / semana |

## M3 — Machine: Como você monta sem travar

> *O erro não é montar a máquina errada. É montar sem critérios — e não saber quando parar ou desligar.*

---

### Princípio 3.1 — Lego Principle

**O que é:** Toda ferramenta da sua stack deve ter uma função específica e se conectar com as demais. Ferramentas que fazem tudo geralmente fazem tudo mal. Ferramentas que fazem uma coisa se encaixam em outras.

### Princípio 3.2 — Validation Chain

**O que é:** Antes de colocar qualquer agente ou automação em produção, você valida cada elo da cadeia separadamente. Um elo quebrado numa cadeia de 5 passos invalida os outros 4.

### Princípio 3.3 — Bike Method (4 fases de autonomia)

**O que é:** Todo agente ou worker começa com rodinha — revisão completa antes de qualquer output ir para o cliente ou para o público. Você tira a rodinha quando tem histórico suficiente para confiar.

```
Fase 1 — TRAINING WHEELS
  Todos os outputs revisados antes de publicar/enviar.
  Avança quando: N outputs aprovados consecutivos sem intervenção.

Fase 2 — GUIDED
  Você revisa 1 em cada 5 outputs. Demais vão direto.
  Avança quando: Semana inteira sem problemas na amostragem.

Fase 3 — WATCHED
  Você revisa relatório semanal. Intervém apenas em exceções.
  Avança quando: 30 dias sem intervenção necessária.

Fase 4 — HANDS-OFF
  Autônomo. Kill Switch ativo. Você só olha se o KPI cair.
```

**Para o agente/automação que você vai construir no programa:**

```

Critério para avançar para Fase 2:
__________________________________________________________

Critério para avançar para Fase 3:
__________________________________________________________

Critério para avançar para Fase 4:
__________________________________________________________
```

### Princípio 3.4 — Intern Rule

**O que é:** Dê para o agente contexto suficiente para que um estagiário inteligente, sem experiência prévia no seu negócio, possa executar sem perguntar. Se você precisaria explicar mais do que isso para um estagiário novo, o agente também vai falhar.

**Checklist de contexto para qualquer agente:**

```
[ ] Tom de voz e estilo de comunicação definidos
[ ] Exemplos de output aprovado incluídos
[ ] Exemplos de output reprovado incluídos
[ ] Restrições explícitas listadas ("nunca faça X")
[ ] Formato de output especificado
[ ] O que fazer em caso de dúvida especificado
[ ] A quem escalar especificado
```

**Para o seu agente do programa:**

Quantos itens do checklist você consegue preencher agora, sem pesquisar?

```
Itens preenchíveis agora: ___ / 7

O que ainda precisa definir antes de começar a montar:
1. ___________________________________________________
2. ___________________________________________________
```

---

### Princípio 3.5 — Kill Switch

**O que é:** Toda automação deve ter um critério claro de desligamento. Se não tem critério de desligamento, você não tem controle — tem dependência.

**Para cada agente/automação que você construir, defina:**

```
Nome: ___________________________________________________

Critério de desligamento automático:
(ex: KPI cai abaixo de X por N dias consecutivos)
__________________________________________________________

Quem pode acionar o Kill Switch: ________________________

O que acontece quando é acionado:
[ ] Para imediatamente
[ ] Completa task atual e para
[ ] Notifica responsável e aguarda

Processo de reativação (quem aprova?): __________________
```

**Regra geral de Kill Switch:**

> Se o custo de manter supera o benefício de operar → desligar.

Custo inclui: tempo de supervisão + custo financeiro + risco de erro + energia mental.
